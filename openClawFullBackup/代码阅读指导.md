# 一、选择哪一份代码作为阅读基线

压缩包中存在多份重复副本：

```text
.openclaw/extensions/celia_memory/
├── install/current/
├── install/v2026-07-07-rc7/
└── package/
    └── openclaw/
```

建议以实际安装版本为唯一基线：

```text
.openclaw/extensions/celia_memory/
└── install/v2026-07-07-rc7/
```

原因：

- `install/current` 只是指向当前版本的软链接或副本；
- `package/openclaw` 是安装前的发行包内容；
- 核心 TypeScript 文件与版本目录中的文件基本重复；
- 实际运行时使用的是 `install/current` 指向的版本目录。

因此不要三份来回对照，避免浪费时间。

## 3. `memory-plugin/src/memory/`：记忆业务行为

路径：

```text
memory-plugin/src/memory/
```

这是 OpenClaw 如何使用 Celia Memory 的业务层。

### 第一优先级

```text
hooks.ts
tools.ts
conversation-sanitizer.ts
runtime-state.ts
store-signal.ts
session-prompt-buffer.ts
fixedContext.ts
l0Sync.ts
l1ScenesSync.ts
```

#### `hooks.ts`

这是另一个最重要的文件。

重点分析：

```text
session_start
after_compaction
before_prompt_build
agent_end
session_end
```

它决定：

- 什么时候召回记忆；
- 什么时候注入 Prompt；
- 什么时候写入本轮对话；
- 什么时候读取 `MEMORYSTATE`；
- 什么时候清理 conversation 状态。

Jiuwen 中需要映射为：

| OpenClaw Hook         | Jiuwen 对应机制                          |
| --------------------- | ---------------------------------------- |
| `before_prompt_build` | `ExternalMemoryRail.before_model_call()` |
| `agent_end`           | `ExternalMemoryRail.after_invoke()`      |
| Service start         | `Provider.initialize()`                  |
| Service stop          | `Provider.shutdown()`                    |
| `session_end`         | Session teardown 或缓存清理              |

#### `tools.ts`

重点看两层映射：

```text
LLM 看到的高级工具
    ↓
底层 Celia MCP 工具
```

尤其关注：

- `memory_store`；
- `memory_forget`；
- `memory_record_search`；
- `memory_chat_history_search`；
- `memory_scene_load`；
- `memory_scene_list_load`；
- `memory_flush`。

不要简单认为高级 Tool 与 MCP Tool 一一同名。

#### `conversation-sanitizer.ts`

这是 Celia 写入质量的关键。

重点看：

- 哪些消息被保留；
- 哪些字段被删除；
- Assistant thinking 是否保留；
- toolCall 如何处理；
- 成功 toolResult 为什么丢弃；
- 失败 toolResult 为什么保留摘要；
- Memory Tool 自身结果为何必须过滤；
- 长参数如何截断。

Jiuwen 完整版接入需要重写等价 Python 逻辑。

#### `runtime-state.ts`

重点看 conversation 级状态如何保存和淘汰，例如：

- 当前已加载的 Scene；
- dirty 状态；
- TTL；
- conversation 清理；
- LRU 上限。

#### `store-signal.ts`

重点理解：

```text
memory_store
并不直接 memory_add
```

它会把当前轮标记成：

```text
deferred-urgent
```

真正写入发生在 `agent_end`。

#### `session-prompt-buffer.ts`

用于用户明确要求“记住”后，在 Celia 异步提取完成前，让该记忆立即在当前 Session 中可见。

这一机制不是 MVP 必需，但对行为一致性有价值。

#### `fixedContext.ts`

负责组织固定注入的记忆上下文，重点看：

- L0；
- L1；
- token/字符预算；
- 格式；
- 去重；
- 注入顺序。

#### `l0Sync.ts`

负责全局用户概览：

```text
memory_get_l0_global_summary
```

以及如何同步到 OpenClaw 上下文。

#### `l1ScenesSync.ts`

负责：

- 获取 L1 index；
- 选择 preset scenes；
- 按 `factCount` 选择动态 scenes；
- 控制固定加载量；
- 场景排序和去重。
