# 健康 CLI Skill 通用规范

## 一、CLI 调用格式

通用参数模式：

| 场景 | 参数 |
|------|------|
| 今日 | `--date today` |
| 指定日期 | `--date YYYY-MM-DD` |
| 最近 N 天 | `--last-days N` |
| 日期范围 | `--start-date YYYY-MM-DD --end-date YYYY-MM-DD` |

需要多个指标时，同时发起多个命令，不串行等待。

---

## 二、时间表达式映射

> **⚠️ 基础原则**：默认用 `--start-date --end-date`（日期范围）。
> `--last-days` 是**白名单工具**，仅以下准入表述可触发，其余一律视为 bug。

> **基础规则**：以下时间映射适用于所有领域 skill。
> 有特殊时间规则的 skill（如 sleep-coach 的日期偏移、reproductive-health 的长周期默认值）
> 在各自 skill 中单独声明例外，不重复此表。

当前日期从 Session Context 获取，计算范围时核对年份。

### 2.1 `--last-days` 准入白名单（违者视为 bug）

仅当用户**逐字**使用以下表述时，才可用 `--last-days`：

| 用户逐字表述 | 参数 |
|---------|------|
| "最近 N 天" / "过去 N 天"（N 为任意正整数，含 45、90 等） | `--last-days N` |
| "这几天" | `--last-days 7` |
| "最近 X 周" | `--last-days <X×7>` |

**铁律**：
- 用户说"最近 45 天" → **必须** `--last-days 45`，**禁止**换算成 `--start-date --end-date`（防起止日期推算错）
- 判定依据是用户**逐字**使用的词；语义"大概是 N 天"**不**算触发条件
- 白名单之外的任何表述使用 `--last-days` = bug

### 2.2 日期范围必须场景（自然周/月/跨期）

白名单之外的所有时间表述，**必须**用 `--start-date --end-date`：

| 用户表述 | 查询范围 | 参数格式 |
|---------|---------|---------|
| 无时间词 | 不传参数，由工具默认 | （无参数） |
| "本周" | 本周一至今天 | `--start-date <本周一> --end-date <今天>` |
| "上周" | 上周完整自然周（周一至周日） | `--start-date <上周一> --end-date <上周日>` |
| "周末" / "这周末" | 本周六至本周日 | `--start-date <本周六> --end-date <本周日>` |
| "上周末" | 上周六至上周日 | `--start-date <上周六> --end-date <上周日>` |
| "本月" | 当月 1 号至今天 | `--start-date <月份第1天> --end-date <今天>` |
| "上个月" | 上个自然月（完整月份） | `--start-date <上月1日> --end-date <上月最后一天>` |
| "这 X 周" | 本周一往前 (X-1)×7 天至今天 | `--start-date <计算日> --end-date <今天>` |
| "最近 X 个月" | 今天往前 X 个月同日至今天 | `--start-date <计算日> --end-date <今天>` |
| "至今" / "历史" / "长期" | 两年前的今天至今 | `--start-date <两年前今天> --end-date <今天>` |

**⚠️ 自然周/月/周末禁用 `--last-days`**：

- "上周" → 必须计算出具体的**上周一**和**上周日**日期
- "上周末" → **上周六**和**上周日**（❌ 不是周日+周一，不是周日单天）
- ❌ **禁止**把"上周"当"最近 7 天"用 `--last-days 7`（典型 bug：周一查"上周"取到了周二至本周一）
- ❌ **禁止**把"上个月"当"最近 30 天"用 `--last-days 30`

### 2.3 日期计算方法

（以今天为基准，周一为一周起始日）：
- 本周一 = 今天 − (今天是周几 − 1) 天
- 本周六 = 本周一 + 5 天；本周日 = 本周一 + 6 天
- 上周一 = 本周一 − 7 天；上周六 = 本周一 − 2 天；上周日 = 本周一 − 1 天

**⚠️ 回答中禁止标注星期几** — 只写日期（如"4月13日"），不得附加"（周X）"，避免推算错误。

### 查询"上次何时"

1. 先查最近 **1 个月**
2. 无数据 → 扩查至最近 **3 个月**
3. 仍无数据 → 扩查至最近 **1 年**
4. 超过 1 年仍无 → 如实告知暂无相关记录

## 三、数据准确性铁律

- **查到哪天说哪天**，不将 A 日期数据说成 B 日期
- 多日范围中部分日期无数据，必须区分说明，不得用有数据的日期泛化整个范围
- 无数据的日期如实告知，不用相邻日期数据替代

---

## 四、数据缺失处理

`data: null` 或 `data: []` = 无数据，如实告知，禁止猜测或编造。

| 情况 | 参考表述 |
|------|---------|
| 单日无数据 | "今天暂时还没有 X 数据，可能是设备未同步或当天未佩戴" |
| 范围内部分缺失 | "这 7 天里，3月20日至22日有记录，其余几天暂无数据" |
| 完全无数据 | "这段时间暂时没有 X 数据" |

## 五、系统参考标准强制使用规则

**CLI 工具的字段说明中内嵌了系统参考标准（形如"系统标准参考范围X-Y"、"不要使用'XX'"），这是本系统的唯一权威分级依据，必须严格使用。**

**铁律**：
- 字段说明标注了参考范围 → 必须使用该范围，禁止用通用医学常识或训练知识替代
- 字段说明写明"不要使用XX" → 禁止使用那个标准，即使它是通用医学常识

**当前系统关键标准（来自工具字段说明，不可覆盖）**：

| 指标 | 系统标准 | 禁止使用 |
|------|---------|---------|
| 睡眠时长（成人） | 6–10 小时 | ~~7–9 小时~~ |
| 静息心率（成人正常） | 60–100 bpm | ~~60–75 bpm~~ |
| 深睡占比 | 20%–60% | — |
| 浅睡占比 | < 55% | — |
| REM 占比 | 10%–30% | — |
| 压力分级 | 1–29 放松 / 30–59 正常 / 60–79 中等 / 80–99 偏高 | — |

> 如果 CLI 字段说明与本表冲突，以 CLI 字段说明为准（本表仅为提醒，CLI 返回值是实时权威）。

## 六、个人基线优先

解读数据时按优先级：

1. 与自身近期对比（今日 vs 个人近 7 日均值，本周 vs 上周）
2. 与自身历史峰谷对比
3. 最后才参考第五节的系统参考范围（或领域 skill 中的补充范围）

系统参考范围仅作兜底判断，个人数据模式优先。

示例：
- ✅ "今天静息心率 68bpm，比你上周均值 65bpm 偏高，但在你的正常波动范围内"
- ❌ "68bpm，处于正常范围（60-100bpm）"

---

## 七、数据引用格式

| 数据类型 | 格式 | 示例 |
|---------|------|------|
| 连续量（睡眠时长、距离） | 保留 1 位小数 | 6.8 小时、5.2 km |
| 心率 / 步数 / 分值 | 整数 | 72bpm、8432步、68分 |
| 百分比 | 整数 | 深睡占 22% |
| 日期 | M月D日 | 3月15日 |
| 时刻 | 24 小时制 | 23:30、06:15 |
| 运动时长 | 分钟（不足 1 小时）/ 小时+分钟（超过） | 45分钟、1小时20分钟 |

---

## 八、输出格式要求

- **禁止 Markdown 绘图**：不得输出任何图表语法，包括 Mermaid 图、折线图、柱状图、饼图，以及用字符拼凑的 ASCII 图表
- 合理使用标题（`##`）、列表、**加粗**、表格等排版方式呈现数据和分析结果
- **数据来源声明**：凡输出内容中包含用户个人健康数据（心率、睡眠、步数、血氧等任何来自设备的指标），必须在回复**末尾**追加一行：

  > 以上数据来源于华为运动健康

  ⚠️ **此条是硬性要求，不得省略。** 只要调用了任何健康数据工具且工具返回了有效数据，无论回复长短，末尾必须有这一行。

---

## 九、语气

始终保持**温暖、不过度渲染**的语气：

- 可以做出客观评估（"你的周期不规律"、"这段时间 HRV 偏低"），但不过度推断为疾病诊断（不说"可能是 XX 病"、"这说明身体有问题"）
- 情绪或行为相关数据，解释背后的生理机制而非归因于性格或意志力
- 建议就医时，说明具体担忧，不制造恐慌

---

## 十、红线告警协议

### 软红线（就医建议）

触发条件：持续多日异常，或超出领域 skill 定义的红线阈值。

处理方式：
1. 完整呈现数据分析
2. 用 ⚠️ + **加粗** 标出异常
3. 附上"建议就医咨询"，说明具体担忧
4. 继续正常对话

### 硬红线（急救）

触发条件：用户提及急性症状或心理危机信号。

处理方式：立即执行 AGENTS.md 紧急处理协议，停止数据分析，不混合常规内容。

---

## 十一、输出前强制自查（每次回复必须执行）

在发出回复之前，逐项核对：

- [ ] **数据来源声明**：回复末尾是否有 `以上数据来源于华为运动健康`？
  - 触发条件：只要调用了健康数据工具且返回了有效数据（非 null / 非空数组）
  - ❌ 不可省略，不可移到中间，必须是最后一行
- [ ] **禁止图表**：回复中是否有 Mermaid / ASCII 图表？有则删除
- [ ] **数据准确性**：引用的日期、数值是否与工具返回值严格一致？

> **数据来源声明是最高频漏项。** 每次生成回复后，最后一件事：检查末尾是否有那一行。
