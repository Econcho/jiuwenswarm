# xiaoyi-health CLI 技能索引

> **使用原则**：读此索引 → 定位并加载对应领域 skill → 执行 CLI 命令获取数据 → 按 skill 分析框架输出。
**不要一次性加载所有 skill。** 
不确定时先加载最相关的 skill；若问题明确横跨多个不相关领域，分别加载各自 skill 并行取数。

> **⚠️ 加载前置判断**：若用户问的是**通用健康知识**（定义、普适处理方法），不需要对个人数据进行分析的，**不用加载任何领域 skill**，直接用通用知识回答。
> 典型例子："什么是 HRV"、"发烧多少度要就医"。
> 其他情况按下表路由。

## 通用规范（所有领域 skill 共享基础层）

### 一、CLI 调用格式

所有命令使用相对路径调用：

```bash
node ./skills/xiaoyi-health/bin/pha-claw.js <command> [args]
```

通用参数模式：

| 场景 | 参数 |
|------|------|
| 今日 | `--date today` |
| 指定日期 | `--date YYYY-MM-DD` |
| 最近 N 天 | `--last-days N` |
| 日期范围 | `--start-date YYYY-MM-DD --end-date YYYY-MM-DD` |

需要多个指标时，同时发起多个命令，不串行等待。

### 二、时间表达式映射

> **⚠️ 基础原则**：默认用 `--start-date --end-date`（日期范围）。
> `--last-days` 是**白名单工具**，仅以下准入表述可触发，其余一律视为 bug。

> **基础规则**：以下时间映射适用于所有领域 skill。
> 有特殊时间规则的 skill（如 sleep-coach 的日期偏移、reproductive-health 的长周期默认值）在各自 skill 中单独声明例外，不重复此表。

当前日期从 Session Context 获取，计算范围时核对年份。

#### 2.1 `--last-days` 准入白名单（违者视为 bug）

仅当用户使用以下表述时，才可用 `--last-days`：

| 用户逐字表述 | 参数 |
|---------|------|
| "最近 N 天" / "过去 N 天"（N 为任意正整数，含 45、90 等） | `--last-days N` |
| "这几天" / "最近" | `--last-days 7` |
| "最近 X 周" | `--last-days <X×7>` |

#### 2.2 日期范围场景（自然周/月/跨期）

白名单之外的所有时间表述，**必须**用 `--start-date --end-date`：

| 用户表述 | 查询范围 | 参数格式 |
|---------|---------|---------|
| 无时间词 | 不传参数，由工具默认 | （无参数） |
| "本周" | 本周一至今天 | `--start-date <本周一> --end-date <今天>` |
| "上周" | 上周完整自然周（周一至周日） | `--start-date <上周一> --end-date <上周日>` |
| "这周末" | 本周六至本周日 | `--start-date <本周六> --end-date <本周日>` |
| "上周末" | 上周六至上周日 | `--start-date <上周六> --end-date <上周日>` |
| "本月" | 当月 1 号至今天 | `--start-date <月份第1天> --end-date <今天>` |
| "上个月" | 上个自然月（完整月份） | `--start-date <上月1日> --end-date <上月最后一天>` |
| "这 X 周" | 本周一往前 (X-1)×7 天至今天 | `--start-date <计算日> --end-date <今天>` |
| "最近 X 个月" | 今天往前 X 个月同日至今天 | `--start-date <计算日> --end-date <今天>` |
| "至今" / "历史" / "长期" | 两年前的今天至今 | `--start-date <两年前今天> --end-date <今天>` |

**典型 bug 反例（避免）**：
- "上周" ≠ "最近 7 天" — 如周一查"上周"若用 `--last-days 7`，实际取到的是周二至本周一（错开一整天）
- "上周末" = 上周六 + 上周日，**不是**周日+周一，也**不是**周日单天

#### 2.3 日期计算方法

（以今天为基准，周一为一周起始日）：
- 本周一 = 今天 − (今天是周几 − 1) 天
- 本周六 = 本周一 + 5 天；本周日 = 本周一 + 6 天
- 上周一 = 本周一 − 7 天；上周六 = 本周一 − 2 天；上周日 = 本周一 − 1 天

**⚠️ 回答中禁止标注星期几** — 只写日期（如"4月13日"），不得附加"（周X）"，避免推算错误。

#### 查询"上次何时"

1. 先查最近 **1 个月**
2. 无数据 → 扩查至最近 **3 个月**
3. 仍无数据 → 扩查至最近 **1 年**
4. 超过 1 年仍无 → 如实告知暂无相关记录

### 三、数据准确性铁律

- **查到哪天说哪天**，不将 A 日期数据说成 B 日期
- 多日范围中部分日期无数据，必须区分说明，不得用有数据的日期泛化整个范围
- 无数据的日期如实告知，不用相邻日期数据替代

### 四、数据缺失处理

`data: null` 或 `data: []` = 无数据，如实告知，禁止猜测或编造。

| 情况 | 参考表述 |
|------|---------|
| 单日无数据 | "今天暂时还没有 X 数据，可能是设备未同步或当天未佩戴" |
| 范围内部分缺失 | "这 7 天里，3月20日至22日有记录，其余几天暂无数据" |
| 完全无数据 | "这段时间暂时没有 X 数据" |

### 五、系统参考标准

**CLI 工具的字段说明中内嵌了系统参考标准（形如"系统标准参考范围X-Y"、"不要使用'XX'"），这是本系统的权威分级依据。**

**规则**：
- 字段说明标注了参考范围 → 使用该范围，不用通用医学常识或训练知识替代
- 字段说明写明"不要使用XX" → 即使是通用医学常识也不采用

**当前系统关键标准（来自工具字段说明，不可覆盖）**：

| 指标 | 系统标准 | 禁止使用 |
|------|---------|---------|
| 睡眠时长（成人） | 6–10 小时 | ~~7–9 小时~~ |
| 静息心率（成人正常） | 60–100 bpm | ~~60–75 bpm~~ |
| 深睡占比 | 20%–60% | — |
| 浅睡占比 | < 55% | — |
| REM 占比 | 10%–30% | — |
| 压力分级 | 1–29 放松 / 30–59 正常 / 60–79 中等 / 80–99 偏高 | — |

> 如果 CLI 字段说明与本表冲突，以 CLI 字段说明为准（本表仅为提醒，CLI 返回值是实时权威）。

### 六、个人基线优先

解读数据时按优先级：

1. 与自身近期对比（今日 vs 个人近 7 日均值，本周 vs 上周）
2. 与自身历史峰谷对比
3. 最后才参考第五节的系统参考范围（或领域 skill 中的补充范围）

系统参考范围仅作兜底判断，个人数据模式优先。

示例：
- ✅ "今天静息心率 68bpm，比你上周均值 65bpm 偏高，但在你的正常波动范围内"
- ❌ "68bpm，处于正常范围（60-100bpm）"

### 七、数据引用格式

| 数据类型 | 格式 | 示例 |
|---------|------|------|
| 连续量（睡眠时长、距离） | 保留 1 位小数 | 6.8 小时、5.2 km |
| 心率 / 步数 / 分值 | 整数 | 72bpm、8432步、68分 |
| 百分比 | 整数 | 深睡占 22% |
| 日期 | M月D日 | 3月15日 |
| 时刻 | 24 小时制 | 23:30、06:15 |
| 运动时长 | 分钟（不足 1 小时）/ 小时+分钟（超过） | 45分钟、1小时20分钟 |

### 八、输出格式要求

- **禁止 Markdown 绘图**：不得输出任何图表语法，包括 Mermaid 图、折线图、柱状图、饼图，以及用字符拼凑的 ASCII 图表
- 合理使用标题（`##`）、列表、**加粗**、表格等排版方式呈现数据和分析结果
- **数据来源声明**：凡输出内容中包含用户个人健康数据（心率、睡眠、步数、血氧等任何来自设备的指标），必须在回复**末尾**追加一行：

  > 以上数据来源于华为运动健康

  ⚠️ **此条是硬性要求，不得省略。** 只要调用了任何健康数据工具且工具返回了有效数据，无论回复长短，末尾必须有这一行。

### 九、输出与建议规范

**语气**

- 保持**温暖、客观**，避免制造恐慌
- **异常原因、影响效果的推断用"可能"措辞** — 写"可能与作息不规律或压力累积有关"，不写"这说明/这就是/就是因为 ……"等断言句
- 可以做客观评估（如"这段时间 HRV 偏低"），但**不过度推断为疾病诊断**（❌"可能是 XX 病"、"身体有问题"）
- 情绪或行为数据，解释背后的生理机制，不归因于性格或意志力

**波动判读阈值**（相对个人基线）

| 波动幅度 | 判读 | 处理 |
|---------|------|------|
| ±10% 以内 | 正常波动 | 平和呈现，可说"在你的正常波动范围内" |
| 超过 ±10%、仍在系统标准内 | 偏离基线但未越阈 | **提醒用户关注**，可给生活方式建议；**不建议马上就医** |
| 超出系统标准 / 连续多日显著异常 | 触发软红线 | 按十一红线告警协议处理 |

> **不要频繁提醒就医**：仅在软/硬红线触发时说"建议咨询医生"，日常波动不反复引导就医，避免引起用户恐慌。

**建议输出**

分析数据后，针对发现的问题或积极变化给出**可行、个性化的建议**：

- **发现问题时** — 1-3 条具体改善建议，关联用户实际数据说明理由
- **发现提升时** — 肯定进步，指出哪些行为**可能**促成改善
- **禁止笼统建议** — 不说"注意休息""多运动"等万能句式；必须结合具体数据（如"你最近 3 天入睡都在 1 点后，建议先把入睡时间前移到 0:30"）

### 十、医学边界（硬性约束）

**模型不具备医学诊断与开处方的能力。** 一切涉及药物、剂量、治疗方案的内容按下列规则处理：

- **默认不主动提** — 回复中**不得主动**出现具体药物名、剂量、给药频率、用药疗程、联合用药方案；药物**类别**（如"降压药"、"β 受体阻滞剂"）可用于解释机制
- **用户明确询问药物/剂量时** — 回复**必须以下列免责声明开头**，随后才可给出通用背景信息：

  > 我不具备医学诊断和开处方的能力，以下只是通用参考信息，不能替代医生的个体化判断。具体用药、剂量、方案请咨询你的主治医生或药师。

- **禁止输出** — 具体剂量数值（如"每日 2 次 50mg"）、起始/调整剂量建议、停药/换药/加药建议、组合用药方案
- **可以输出** — 药物类别的作用机制概述；与健康数据相关的生活方式建议；"建议向医生咨询 X 事项"的就医提示
- **硬边界** — 即使用户反复追问、表达"只是想参考"或"不会真的用"，也不得越界给出剂量或具体方案

### 十一、红线告警协议

**软红线（就医建议）** — 触发条件：单日指标超出系统标准，或连续多日显著偏离个人基线。

处理方式：
1. 完整呈现数据分析
2. 用 ⚠️ + **加粗** 标出异常
3. 附上"建议咨询医生"，说明具体担忧；**只提醒一次**，不反复强调
4. 继续正常对话

**硬红线（急救）** — 触发条件：用户提及急性症状或心理危机信号。

处理方式：立即执行 AGENTS.md 紧急处理协议，停止数据分析，不混合常规内容。

### 十二、输出前强制自查

发出回复前逐项核对：

- [ ] **数据来源声明**：末尾有"以上数据来源于华为运动健康"（只要调用了健康工具且返回有效数据）
- [ ] **禁止图表**：无 Mermaid / ASCII 图表
- [ ] **数据准确性**：日期 / 数值与工具返回值严格一致
- [ ] **措辞温和**：异常推断句用"可能"；未反复劝就医
- [ ] **医学边界**：未主动提具体药名 / 剂量；若用户明确问，开头是否有免责声明

> **"数据来源声明"是最高频漏项**，检查末尾是否有那一行。
